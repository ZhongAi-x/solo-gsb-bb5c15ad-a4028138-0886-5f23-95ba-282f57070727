# 桌游联赛 · 瑞士制配对 Web 应用

基于 **React + TypeScript + Vite** 的单页应用，用于桌游联赛的瑞士制（Swiss）配对编排：
录入选手（可选队伍）与各轮赛果/轮空后，一键生成下一轮对阵——在禁止重复交手前提下，
按「同队对局数 → 跨积分组对局数 → 总积分差」全局最小化；支持锁定人工指定对局后重算，
支持勾选本轮缺席选手（只配出席者），并在约束无解时列出冲突原因。
支持把整届赛事导出为带 `schemaVersion` 的 JSON 快照文件，并在导入前完成内存规范化与全量校验、
二次确认后才替换当前赛事。

## 一条命令启动（Docker Compose）

前置条件：已安装 Docker 与 Docker Compose 插件。

```bash
docker compose up --build -d
```

容器启动时会**自动完成依赖安装（`npm install`）与生产构建（`tsc && vite build`）**，随后启动静态服务。

- 访问地址：**http://localhost:8080**
- 监听端口：**8080**（宿主机与容器内一致）

查看日志 / 停止：

```bash
docker compose logs -f
docker compose down
```

如需更换端口，修改 `docker-compose.yml` 中 `"8080:8080"` 左侧端口（例如 `"9000:8080"`）后重新启动即可。

也可以不使用 Compose：

```bash
docker build -t swiss-pairing .
docker run --rm -p 8080:8080 swiss-pairing
# 访问 http://localhost:8080
```

## 本地开发（不用 Docker）

要求 Node.js ≥ 18。

```bash
npm install
npm run dev        # 开发服务器，访问 http://localhost:5173
```

其他命令：

```bash
npm run build         # 类型检查 + 生产构建（输出到 dist/）
npm run preview       # 本地预览生产构建（http://localhost:4173）
npm run test:engine   # 运行规则自测（共 36 个场景：配对引擎、本轮缺席、快照导入导出与旧数据迁移）
```

## 赛事快照导入 / 导出

顶部操作区提供「导入快照」「导出快照」按钮，用于备份或在不同浏览器/设备间迁移整届赛事。
快照是一个带 `schemaVersion` 的 JSON 文件，**完整包含**：

- `players`：选手 id、姓名与可选队伍；
- `rounds`：每一轮的对局（双方选手 id、赛果 `resultA`、轮空标记）与该轮 `absentIds` 缺席快照。

文件示例（`exportedAt` 为导出时间戳，仅作记录）：

```json
{
  "kind": "swiss-pairing-snapshot",
  "schemaVersion": 1,
  "exportedAt": "2026-09-20T08:00:00.000Z",
  "players": [{ "id": "p_1", "name": "张三", "team": "红队" }],
  "rounds": [
    {
      "id": "r_1",
      "matches": [{ "id": "m_1", "playerAId": "p_1", "playerBId": null, "resultA": "win", "bye": true }],
      "absentIds": []
    }
  ]
}
```

### 导出

- 点击「导出快照」下载 `swiss-tournament-YYYYMMDD-HHMMSS.json`，内容取自当前 localStorage 中的赛事，
  导出过程不改动任何数据。

### 导入（先校验、后确认，绝不部分导入）

1. 点击「导入快照」选择 JSON 文件后，解析、**规范化与全量校验全部在内存中完成**，此时不会改动当前赛事。
2. 校验通过时弹窗**仅展示数量与问题预览**（选手/队伍/轮次/对局/轮空/待录赛果数，以及迁移记录与非阻塞问题）。
3. 只有在用户点击「确认导入并替换当前赛事」后，才会**一次性替换**全部选手、轮次与赛果，
   同时清空下一轮工作区的**临时锁定对局与缺席勾选**。
4. 校验失败时按 **JSON 路径**逐条列出错误并禁止导入（不会有任何部分写入）。

导入时执行的校验包括：

| 校验项 | 规则 |
| --- | --- |
| 文件格式 | 必须是合法 JSON，顶层为对象；`schemaVersion` 缺失按旧版迁移，高于当前版本直接拒绝 |
| ID 唯一 | 选手、轮次、对局的 id 在各自作用域/全局内不得重复，且必须是非空字符串 |
| 对局引用 | `playerAId` / `playerBId` 必须存在于选手名单；同一对局双方不得为同一人 |
| 同轮不重复 | 每名选手在同一轮（含轮空）至多出现一次，且不能同时出现在该轮缺席名单中 |
| 轮空结构 | 轮空对局必须 `playerBId === null` 且 `bye === true`（旧数据缺少 `bye` 时按结构推断） |
| 赛果取值 | `resultA` 只允许 `"win"` / `"draw"` / `"loss"` / `null`；轮空对局必须为 `"win"` |

旧版迁移规则：缺少 `schemaVersion` 视为旧版快照；任何一轮缺少 `absentIds` 时**迁移为空数组**；
选手姓名与队伍名会做去首尾空白等规范化；`absentIds` 若引用了名单中已不存在的选手（例如先删人再导出），
会在问题预览中标出并在导入时忽略，不阻塞导入。注意：**对局引用的选手缺失属于硬错误**
（用于删除选手后又保留了历史轮次的旧数据），此时请先恢复对应选手或在原环境整理后再导出。

非阻塞问题（同名选手、跨轮重复交手等）只在预览中提示，不影响导入。导入后数据仍自动写入 localStorage。

## 选手与队伍字段格式

- **选手姓名**：1–24 个字符，整届赛事内建议唯一（积分榜按姓名并列时再按 id 区分）。
- **队伍名称（可选）**：1–16 个字符；留空表示无队伍，不参与同队回避。
  队伍名仅保存在选手资料上，**历史轮次只记录选手 id，不记录当时队伍**：
  随时修改/清空某选手的队伍，已完成轮次的赛果与积分都不会变化，下一轮配对按最新队伍计算。
- **单个添加**：输入框可只填姓名，也可一次带上队伍：

  ```
  张三
  张三|红队
  ```

- **批量录入**：每行一名选手，行内用 `|`、制表符或冒号（`:`/`：`）分隔姓名与队伍，队伍可省略：

  ```
  张三|红队
  李四 | 红队
  王五：蓝队
  赵六
  ```

  分隔符两侧空白会被自动去除；超过 32 人上限的部分将被忽略。

## 配对规则

1. **禁止重复交手**：任何两名选手在整届赛事中最多对阵一次（以历史轮次记录为准）。
2. **优化目标（字典序，依次满足）**：
   1. **同队对局数最少**（双方填写了相同的非空队伍名即为同队；无队伍的选手不参与该判定）；
   2. 在同队数相同的方案中，跨积分组对局数最少（积分相同者视为同一积分组，优先组内配对）；
   3. 在以上两项相同的方案中，所有对阵双方的**总积分差之和最小**。
   求解使用带 MRV 启发与同队/跨组奇偶下界剪枝的分支限界搜索；≤32 人规模下可保证或快速逼近最优
   （达到节点预算时界面会明确标注“可行方案，未证明最优”）。
3. **同队冲突提示**：当受历史交手、奇数轮空或人工锁定约束而无法完全回避同队时，
   方案区会红色标出每一场同队对局（含队名），并显示**全局最少同队场次数及涉及选手**。
4. **奇数人轮空**：人数为奇数时，每轮安排一人轮空并计 1 分（按胜场计分）。
   轮空者依次选择：**尚未轮空过 → 当前积分最低**（并列时按对手分 Buchholz、姓名）；
   若所有人都已轮空过，则在未被锁定占用的选手中选择积分最低者并给出提示。
5. **人工锁定**：可在工作区手工指定任意对局（或直接锁定系统生成的某一场），
   系统在保留全部锁定对局的前提下，对其余选手重新执行完整优化。
   **锁定的同队对局允许保留**（不会被判为非法），但会计入方案的同队/跨组/积分差指标，界面会额外提示。
6. **本轮缺席**：在工作区「本轮缺席」区勾选本轮不参赛的选手后，配对、轮空候选与人工锁定都只使用出席者。
   缺席**不会删除选手**，也**不改动历史积分**；确认轮次时缺席名单会快照保存进该轮记录，
   历史轮次区随对阵一起展示，刷新后保持一致（旧版本本地数据升级时缺席名单一律视为空）。
   若某条**已锁定对局**的一方被标记缺席，会立即判为冲突并阻止确认，指出涉及选手；
   取消缺席（或移除该锁定）后，系统按原约束自动重新计算。
7. **冲突诊断**：当锁定行本身非法（双方为同一人、选手重复出现在多行、与历史交手重复、含本轮缺席选手），
   或在「禁止重复交手」下已无可行完整配对时，界面会逐条列出冲突原因，
   例如某选手与所有其余选手均已交手、奇数人数下无人可轮空等。

## 赛果与积分

- 胜 = 1 分，和 = 0.5 分，负 = 0 分，轮空 = 1 分。
- 积分榜按积分降序，同分依次比较对手分（Buchholz，轮空轮不计入对手分）、姓名。
- 上一轮存在未录入赛果的对局时，工作区会给出醒目提示（仍可强制继续）。
- 所有数据保存在浏览器 **localStorage**，刷新不丢失；“清空重置”可清除全部数据。
  需要跨浏览器/设备迁移或留档时，使用顶部「导出/导入快照」（见上文“赛事快照导入 / 导出”）。

## 操作流程

1. 在「选手名单」中单个或批量录入选手（最多 32 人；可用「姓名|队伍」格式填写可选队伍；
   首次使用可点「载入 6 人示例」，示例含红队/蓝队各 3 人）。队伍随时可在名单行内直接修改，不影响历史赛果。
2. 在「第 N 轮对阵工作区」查看自动生成的方案（含同队/跨组/积分差标记与轮空安排）。
   若无法完全回避同队，方案区会显示最少同队场次及涉及选手。
   如有选手本轮不参赛，在「本轮缺席」区勾选其姓名，配对立即只在出席者中重算。
3. 需要干预时：点某场对局的「🔒 锁定此场」，或「＋ 添加人工指定对局」自行选择双方；
   其余配对即时重算。锁定同队对局会被保留并计入指标；锁定对局含缺席选手会被判冲突并阻止确认。
4. 确认无误后点「✓ 确认方案，进入第 N 轮」，本轮缺席名单随轮次一并保存。
5. 在「已完成轮次」中录入每场结果（A 胜 / 和棋 / B 胜），积分榜与下一轮对阵随即更新；
   各轮缺席名单在历史区随对阵一并展示。
6. 需要备份或迁移时，用顶部「导出快照」下载整届赛事 JSON；在另一环境点「导入快照」，
   通过校验预览并二次确认后即完成整体替换（工作区临时锁定与缺席勾选会被清空）。

## 项目结构

```
.
├── Dockerfile                # 基于 node:20-alpine 的镜像定义
├── docker-entrypoint.sh      # 启动入口：npm install → npm run build → vite preview
├── docker-compose.yml        # 一条命令编排（端口 8080）
├── index.html
├── package.json
├── vite.config.ts
├── scripts/
│   └── selftest.ts           # 规则自测（配对引擎、本轮缺席、快照导入导出/迁移）
└── src/
    ├── main.tsx              # React 入口
    ├── App.tsx               # 状态管理与页面编排（含快照导入/导出按钮与替换逻辑）
    ├── types.ts              # 数据模型（Player 含可选 team 字段；Round 含 absentIds 缺席快照）
    ├── engine.ts             # 瑞士制核心：积分、轮空、同队回避、缺席过滤、分支限界配对、冲突诊断
    ├── storage.ts            # localStorage 持久化（含旧数据迁移：缺席名单缺省视为空）
    ├── snapshot.ts           # 赛事快照：带 schemaVersion 的导出 JSON、解析规范化与全量校验（错误按 JSON 路径列出）
    ├── ImportSnapshotDialog.tsx # 导入预览弹窗：数量/问题预览、错误清单、二次确认替换
    ├── uid.ts
    ├── PlayersPanel.tsx      # 选手/队伍录入（≤32 人，支持批量与行内改队）
    ├── StandingsTable.tsx    # 积分榜（含队伍列）
    ├── NextRoundPanel.tsx    # 下一轮工作区：生成/锁定/同队标记/冲突展示/确认
    ├── RoundsPanel.tsx       # 历史轮次与赛果录入
    └── styles.css
```
